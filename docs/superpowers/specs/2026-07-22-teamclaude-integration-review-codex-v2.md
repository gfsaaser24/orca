## 3. NEW

- **N1 — Scoped base-URL cleanup lacks a complete ownership/origin contract.** §§2 and 4 scope deletion to the configured loopback port, but TeamClaude supports pinned paths such as `/tc-acct/deepseek`, while its current dead-proxy regex recognizes only the bare origin with an optional slash ([design §2](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:21), [index.js](C:/code/teamclaude/src/index.js:672), [server.js](C:/code/teamclaude/src/server.js:220)). Parse URLs and compare origins regardless of path/query, and track previously owned ports; otherwise stale pinned or pre-port-change values survive.

- **N2 — A port change can orphan an owned detached proxy.** `config.ts` reinitializes the supervisor on port change, while the ownership policy normally leaves the detached server alive and retains only one marker ([design §4](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:51), [design supervisor](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:69)). TeamClaude captures its port once and reload does not rebind it, so migration must stop the old owned process before replacing its marker ([index.js](C:/code/teamclaude/src/index.js:195), [index.js](C:/code/teamclaude/src/index.js:224)).

- **N3 — Windows ownership markers identify a wrapper, not necessarily the listener.** The current desktop needs `shell:true` to resolve `teamclaude.cmd`, and its recorded child PID belongs to the shell wrapper; it uses `taskkill /T` because killing that PID alone orphans the Node proxy ([design §4](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:69), [supervisor.ts](C:/code/teamclaude/desktop/src/main/supervisor.ts:134)). PID-to-port validation therefore rejects legitimate wrapper ownership or proves too little; spawn the resolved Node entrypoint directly or define descendant-aware validation and tree termination.

- **N4 — Phase-0 writes expand an unauthenticated loopback control surface.** v2 adds persistent routes and account mutations while retaining the rule that every loopback HTTP caller bypasses `x-api-key` ([design §3](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:35), [server.js](C:/code/teamclaude/src/server.js:53)). Require authentication for mutation endpoints even if forwarding and CONNECT remain loopback-exempt.

- **N5 — Endpoint persistence does not specify live application.** `AccountManager` copies routes, priority, and disabled state into runtime objects, and current callers explicitly call `setRoutes`/`setDisabled` or reload after disk changes ([design §3](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:35), [account-manager.js](C:/code/teamclaude/src/account-manager.js:46), [tui.js](C:/code/teamclaude/src/tui.js:620), [index.js](C:/code/teamclaude/src/index.js:224)). Each endpoint needs an atomic disk-plus-runtime transaction or an awaited reload before returning success.

- **N6 — Names and indices are unsafe control-plane identifiers.** Phase 0 accepts route names/indices and targets account updates by name, although indices shift after removal and route tokens match either `account.name` or its stringified index ([design §3](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:35), [account-manager.js](C:/code/teamclaude/src/account-manager.js:356), [account-manager.js](C:/code/teamclaude/src/account-manager.js:933)). Numeric names can be ambiguous and stored indices can silently retarget; expose an opaque stable account ID based on the existing UUID-plus-organization identity.

- **N7 — Certificate preflight adds a generation race.** Even after supplying the missing hostname, raw `ensureCerts` uses identical PID-based temporary names and publishes CA, leaf, and key separately, while only the CONNECT path currently serializes calls through a shared promise ([design §3](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:38), [mitm.js](C:/code/teamclaude/src/mitm.js:47), [server.js](C:/code/teamclaude/src/server.js:167)). The endpoint and CONNECT path must share one process-wide generation lock.

- **N8 — Capabilities lack a vocabulary and readiness semantics.** v2 allows an old server to be `adopted-degraded` yet suppresses native usage whenever transport state is merely connected; current status has none of the proposed version/capability fields ([design §4](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:67), [design usage](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:86), [account-manager.js](C:/code/teamclaude/src/account-manager.js:983)). Define versioned capability names and derive validated states such as `usageReady`, `routingReady`, and `controlReady`.

- **N9 — `/log` cannot be safely assigned the proposed `bootId`.** Phase 0 adds `bootId` only to status and SSE hello, while Activity seeds from `/log`, whose current response contains only `{events}` ([design §3/§5](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:39), [server.js](C:/code/teamclaude/src/server.js:88)). A restart between requests can associate seed events with the wrong boot; `/log` must atomically return `{bootId, events}` or each event must carry its boot ID.

- **N10 — Connected snapshots have no truthful freshness timestamp.** TeamClaude restores quota passively, its background probe defaults off, and neither persisted nor status quota records when a bucket was observed ([design §4](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:86), [index.js](C:/code/teamclaude/src/index.js:146), [account-manager.js](C:/code/teamclaude/src/account-manager.js:8)). Treating HTTP receipt time as freshness would violate Orca’s `updatedAt` contract, so Phase 0 needs per-account or per-bucket `observedAt` plus explicit stale behavior ([rate-limit-types.ts](C:/code/orca-ide/src/shared/rate-limit-types.ts:79)).

- **N11 — Entering the usage short-circuit can lose a rotated refresh token.** Inactive usage awaits a single-use OAuth refresh and then checks cancellation before persisting the replacement; the refresh primitive itself does not accept the service’s signal ([design §4](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:86), [claude-fetcher.ts](C:/code/orca-ide/src/main/rate-limits/claude-fetcher.ts:1300), [oauth-refresh.ts](C:/code/orca-ide/src/main/claude-accounts/oauth-refresh.ts:124)). The connection transition needs quiesce/epoch semantics that stop new refreshes but always commit an already-completed rotation.

- **N12 — The global usage gate conflicts with unrouted WSL/SSH work.** v2 leaves remote agents direct but replaces usage whenever local TeamClaude is connected, whereas `RateLimitService` deliberately tracks a host-versus-WSL Claude target ([design §1/§4](C:/code/orca-ide/docs/superpowers/specs/2026-07-22-teamclaude-integration-design.md:16), [service.ts](C:/code/orca-ide/src/main/rate-limits/service.ts:193), [runtime-selection.ts](C:/code/orca-ide/src/main/claude-accounts/runtime-selection.ts:7)). TeamClaude meters must gate only host-local targets; remote native usage should remain separate and visibly labeled.
